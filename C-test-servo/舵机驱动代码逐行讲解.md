> 对应代码：`servo/error/User/`

## 一、三层结构

```
main.c  (只认识应用层)
  │
  ├── ServoApp_xxx()      应用层   User/app/servo_app.c     说"角度"
  │      │
  │      └── BusServo_xxx()  驱动层   User/driver/bus_servo.c  说"ID + PWM + 时间"
  │             │
  │             └── BspUart_xxx()  BSP层  User/bsp/bsp_uart.c  说"字节"
  │                    │
  │                    └── HAL_UART_xxx()  →  USART3  →  PB10
```

**依赖方向只能从上往下。**

| 层 | 它知道什么 | 它**不知道**什么 |
|---|---|---|
| 应用层 | 4 颗舵机、270°、限速 300°/s | UART、帧格式、PWM 值 |
| 驱动层 | `#001P1500T1000!`、回读解析 | 角度、机械行程、几颗舵机 |
| BSP 层 | 波特率、收发字节、回显 | 舵机、ID、协议 |

---

## 二、为什么这么分（三条硬规则）

### 规则 1：下层不许调用上层

`bsp_uart.c` 里**不会**出现 `BusServo_` 或 `ServoApp_`。
`bus_servo.c` 里**不会**出现 `ServoApp_`。

违反这条，代码就变成一个环，改一处全崩。

### 规则 2：下层不认识上层的概念

- `bsp_uart` 的函数名叫 `Send/Recv`，不叫 `SendToServo` —— 换成接 LoRa 模块，这层不用改
- `bus_servo` 的函数只收 `pwm`，不收 `deg` —— 舵机不知道自己装在机械臂第几节

### 规则 3：跨层只通过头文件，不共享全局变量

`servo_app.c` 内部的 `s_servo[]` 是 `static` 的，外面看不见，只能通过 `ServoApp_SetAngle()` 改。

**三条规则带来什么好处**（都是你后面真的会遇到的）：

| 场景 | 不做解耦 | 做了解耦 |
|---|---|---|
| 舵机从 USART3 换到 USART2 | 翻遍所有文件找 `huart3` | 改 `main.c` 一行 |
| 换成大疆/ Feetech 总线舵机 | 重写全部 | 只重写 `bus_servo.c` |
| 加第 5 颗舵机 | 到处补 `if` | 改 `SERVO_NUM` 和数组 |
| 想单独测串口通不通 | 得连着舵机一起测 | 直接调 `BspUart_Send` |

## 四、BSP 层

### 4.1 `bsp_uart.h`

```c
#ifndef __BSP_UART_H
#define __BSP_UART_H
```
**头文件保护**。同一个 `.h` 被两个 `.c` 同时 `#include` 时，防止内容被展开两遍导致"重复定义"。

```c
#include "main.h"
```
`main.h` 里包含 `stm32f1xx_hal.h`，所以这一行就拿得到了 `UART_HandleTypeDef`、`HAL_UART_Transmit`、`__HAL_UART_GET_FLAG` 这些。

不直接 `#include "stm32f1xx_hal.h"` 是因为 `main.h` 会带上工程级的宏配置（比如 `USE_HAL_DRIVER`），漏了会一堆编译错误。

```c
#define BSP_UART_OK      (0)
#define BSP_UART_ERR     (-1)
```
**用宏而不是 `true/false`**，是因为后面驱动层要区分"发送失败"和"等待超时"等好几种错误。这里先定最基础的两个。

用 `0 / -1` 而不是 `1 / 0`，是让 `if (ret)` 这种写法**失败时为真**，符合 C 的习惯。

```c
void BspUart_Init(UART_HandleTypeDef *huart_bus);
```
`UART_HandleTypeDef *` 而不是 `UART_HandleTypeDef`，是因为**结构体很大**（几十字节），传指针只复制 4 字节。

`huart_bus` 这个名字里的 `bus` 表示"这条串口是总线"，跟调试串口区分开。

```c
int BspUart_Send(const uint8_t *data, uint16_t len, uint32_t timeout_ms);
```
- `const uint8_t *`：**const 是承诺"我不改你的数据"**，调用方传 `char*` 也能进得来
- `uint8_t` 而不是 `char`：串口传的是**字节**，不是字符。`char` 在某些平台是有符号的，做数值运算会出错
- `uint16_t len`：一次最多发 65535 字节，够用又省内存

### 4.2 `bsp_uart.c`

```c
static UART_HandleTypeDef *s_bus = NULL;
```
**`static` 文件级私有变量**。`s_` 前缀表示 static，外部文件拿不到它。

只保存**指针**（4 字节），不保存整个结构体，省 RAM。

初始化为 `NULL`，这样万一有人没调 `Init` 就直接 `Send`，下面会检查出来，不会跑飞。

```c
void BspUart_Init(UART_HandleTypeDef *huart_bus)
{
  s_bus = huart_bus;
  BspUart_DropRx();
}
```
第一行记下用哪条串口。
第二行清一次接收寄存器——因为**上电时可能已经收到垃圾数据**（比如舵机初始化吐的字节），不清掉后面第一帧就错位了。

```c
if ((s_bus == NULL) || (data == NULL) || (len == 0U))
{
  return BSP_UART_ERR;
}
```
**三个入口检查**，一个都不能少：
- `s_bus == NULL`：没调 Init
- `data == NULL`：传了空指针
- `len == 0`：HAL 收到 0 会直接返回 OK，但什么都不做，属于"静默失败"

`0U` 的 `U` 表示无符号常量，避免和 `int` 比较时编译器警告。

```c
if (HAL_UART_Transmit(s_bus, (uint8_t *)data, len, timeout_ms) != HAL_OK)
```
- `(uint8_t *)data`：**去掉 const 强转**。HAL 的形参没写 const（历史遗留），但它内部只读。这是唯一合法的强转场景
- `!= HAL_OK`：HAL 成功返回 `HAL_OK`（0），超时返回 `HAL_TIMEOUT`（3），错误返回 `HAL_ERROR`（1）。**只要不是 OK 就算失败**

```c
void BspUart_DropRx(void)
{
  volatile uint32_t tmp;
```
`volatile` 告诉编译器"这个变量的读写不能被优化掉"。因为读 `DR` 寄存器有**副作用**（会清 `RXNE` 标志），如果编译器觉得 `tmp` 没用就删掉这行，清标志的动作也跟着没了。

```c
  while (__HAL_UART_GET_FLAG(s_bus, UART_FLAG_RXNE) != RESET)
  {
    tmp = s_bus->Instance->DR;
  }
```
`RXNE` = Receive Not Empty，"接收寄存器里有新字节"。
**读 `DR` 会自动清 `RXNE`**，所以这个 `while` 循环就是一个一个把残留字节读空。

`Instance` 是 HAL 句柄里指向寄存器基地址的成员，`->DR` 就是数据寄存器。

```c
  tmp = s_bus->Instance->SR;
  tmp = s_bus->Instance->DR;
```
**STM32F1 清"溢出错误 ORE"的方法就是"先读 SR 再读 DR"**，这是 RM0008 规定的，少一步都清不掉。

不清理 ORE 的后果：下一次 `HAL_UART_Receive` 一进来检查到 ORE，直接返回 `HAL_ERROR`，**你会以为是舵机没回话，其实是自己堵住了**。

```c
uint32_t BspUart_Millis(void)
{
  return HAL_GetTick();
}
```
`HAL_GetTick()` 由 SysTick 中断每 1ms 加一，是**整个工程唯一的时间基准**。

**为什么不直接用 `HAL_GetTick()`？** 因为以后你想换成定时器计时、或者想单元测试时注入假时间，只改这一个函数。

## 五、驱动层

### 5.1 协议要点（来自 2022-04-19 版说明书）

| 项目 | 格式 |
|---|---|
| 单颗控制 | `#001P1500T1000!` |
| ID | 3 位，不足补 0，`001` 不能写 `1` |
| PWM | 4 位，500~2500，`800` 要写 `0800` |
| 时间 | 4 位，0~9999（ms） |
| 多颗同步 | `{G0000#001P...#002P...#003P...#004P...}` |
| 读位置 | 发 `#001PRAD!`，回 `#001P1500!` |
| 读温压 | 发 `#001PRTV!`，回 `#001T28.1V7.4!` |
| 探测 | 发 `#001PID!`，在就回 `#001P!` |

### 5.2 `bus_servo.h`

```c
#define BUS_SERVO_PWM_MIN       (500U)
#define BUS_SERVO_PWM_MAX       (2500U)
```
**这些数字只在头文件里出现一次。** 应用层写 `BUS_SERVO_PWM_MAX` 而不是 `2500`，以后换型号只改这一行。

```c
typedef enum
{
  BUS_SERVO_OK = 0,
  BUS_SERVO_ERR_PARAM = -1,
  ...
} bus_servo_status_t;
```
`enum` 而不是 `#define 0/1/2`：**调试时能看到变量名**，而且编译器会检查类型。

错误码带具体含义，是为了**故障时能分辨原因**：

| 错误码 | 说明什么 |
|---|---|
| `ERR_PARAM` | 你代码写错了（传了 3000 的 PWM） |
| `ERR_SEND` | 串口发不出去（时钟没配？） |
| `ERR_TIMEOUT` | 舵机不回话（没接线？ID 不对？） |
| `ERR_FORMAT` | 回了，但格式乱（波特率不对） |

**这四种错误的排查方向完全不同**，所以必须分开。

### 5.3 `bus_servo.c` 的三个内部函数

#### `send_cmd()` —— 发命令

```c
len = (uint16_t)strlen(cmd);
```
用 `strlen` 而不是让调用方传长度：**减少一个可以传错的参数**（传错了就少发几个字节，很难查）。

```c
if (BspUart_Send((const uint8_t *)cmd, len, CMD_TIMEOUT_MS) != BSP_UART_OK)
```
`(const uint8_t *)cmd`：`char*` → `uint8_t*` 的转换，字符在内存里就是字节，转换是安全的。

```c
BspUart_DropRx();
```
**这一行是本驱动最关键的坑。**

半双工模式下，USART 的接收端**内部接在自己的发送端上**。你发出去的 15 个字节，会被自己完整收回来一遍。

如果不清掉：
```
你发  #001PRAD!        → 线上同时"回显"了 #001PRAD!
清空？没清！
读回复 → 读到 #001PRAD!   ← 这是自己的命令！
解析 → rsp[4] = 'R' ≠ 'P' → 报 ERR_FORMAT
```
你会以为舵机回了垃圾，其实是**把自己的命令当成了回复**。

更坏的情况：`#001PRAD!` 和 `#001P1500!` 一样以 `#` 开头、`!` 结尾，长度也接近，**校验能过**，最后解析出一个错误的数值。

#### `read_reply()` —— 收回复

```c
uint32_t start = BspUart_Millis();
while ((BspUart_Millis() - start) < timeout_ms)
```
**用减法判断超时，不用加法**：`(now - start) < timeout` 在 `HAL_GetTick()` 溢出回绕时依然正确；`now > start + timeout` 会错。

`HAL_GetTick()` 是 `uint32_t`，49.7 天溢出一次，比赛不会碰到，但这是标准写法。

```c
if (BspUart_Recv(&ch, 1U, 1U) != BSP_UART_OK)
{
  continue;
}
```
**每次只收 1 个字节，超时 1ms**。因为回复长度不固定（`#000P!` 6 字节，`#000T28.1V7.4!` 14 字节），只能一个字节一个字节收。

`continue` 而不是 `return`：1ms 没收到字节是正常的（字节之间本来就有间隔），继续等。

```c
if ((n == 0U) && (ch != '#'))
{
  continue;
}
```
**帧同步**。上电瞬间、插拔瞬间可能收到半个字节或杂波，在**看到 `#` 之前收到的全部丢掉**。

这一行让驱动对"半截数据"免疫。

```c
if (ch == '!')
{
  buf[n] = '\0';
  return BUS_SERVO_OK;
}
```
`!` 是协议规定的帧尾。收到就是完整的一帧。

`buf[n] = '\0'` 补字符串结束符，这样后面才能用 `strlen`、`strchr`。

#### `parse_digits()` —— 解析数字

```c
if ((s[i] < '0') || (s[i] > '9'))
{
  return -1;
}
```
**逐字符检查是不是数字**。`atoi` 不做检查——遇到 `#` 会返回 0，你根本不知道出错了。

`-1` 表示失败，因为合法的 PWM 值最小是 500，**不可能是负数**，可以安全地用它当错误标志。

#### `parse_tenths()` —— 解析 `28.1`

```c
if (*s == '.')
{
  s++;
  has_dot = 1U;
  ...
}
```
处理小数点。协议里温度和电压都是**一位小数**（`28.1`、`7.4`）。

```c
*end = s;
```
**输出参数**告诉调用方"我解析到哪儿停了"。调用方靠它找到后面的 `V`，继续解析电压。

这是 C 里实现"返回两个值"的常用手法。

```c
return (value * 10) + (has_dot ? tenth : 0);
```
**放大 10 倍存成整数**：`28.1` → `281`。

为什么不用 `float`：
- 嵌入式里浮点运算慢（F103 没有 FPU，软件模拟）
- `printf("%f")` 要额外链接库，多占好几 KB Flash
- 整数比较 `temp > 600` 比 `temp > 60.0f` 更可靠

### 5.4 对外函数逐个看

#### `BusServo_SetPwm()`

```c
n = snprintf(cmd, sizeof(cmd), "#%03uP%04uT%04u!", id, pwm, time_ms);
```

| 格式符 | 作用 | 例 |
|---|---|---|
| `%03u` | 无符号十进制，宽 3，**左边补 0** | `1` → `001` |
| `%04u` | 宽 4，补 0 | `1500` → `1500`，`800` → `0800` |

**`snprintf` 而不是 `sprintf`**：第二个参数 `sizeof(cmd)` 限制了最多写多少字节，**永远不会缓冲区溢出**。写 `sprintf`，一旦算错就是踩内存，现象是"随机死机"。

```c
if ((n <= 0) || (n >= (int)sizeof(cmd)))
```
- `n < 0`：格式化出错
- `n >= sizeof(cmd)`：**被截断了**（说明缓冲区不够大）

`(int)sizeof(cmd)` 强转是因为 `sizeof` 返回 `size_t`（无符号），和 `int` 比较会警告。

#### `BusServo_SetPwmSync()`

```c
n = snprintf(cmd, sizeof(cmd), "{G0000");
len = n;
```
`{G0000` 是多舵机指令的固定头。`G` 是组号，填 0000 即可。

**为什么必须用这个函数，而不是循环调 4 次 `SetPwm`：**

```
循环调 4 次：
  发 #001 → ① 开始动
  发 #002 → ② 开始动      ← 晚了几百微秒
  发 #003 → ③ 开始动
  发 #004 → ④ 开始动

一帧发完：
  发 {G0000#001#002#003#004}
       ↓
  四颗在同一时刻收到，同时启动
```

**机械臂四个关节不同时动，会互相拉扯**，轻则动作变形，重则堵转烧舵机。

```c
n = snprintf(cmd + len, sizeof(cmd) - (size_t)len, "#%03uP%04uT%04u!", ...);
```
`cmd + len`：**接着上一次的位置往后写**。
`sizeof(cmd) - len`：**剩余空间**。

这两个参数一起用，才能保证"追加"而不越界。

## 六、应用层

### 6.1 `servo_unit_t` —— 一颗舵机的全部信息

```c
typedef struct
{
  uint8_t  id;          /* 舵机 ID */
  uint16_t range_deg;   /* 机械行程 270 或 180 */
  int16_t  offset_deg;  /* 安装偏差 */
  uint16_t speed_dps;   /* 限速 度/秒 */
  int16_t  cur_deg;     /* 当前角度 */
  int16_t  tgt_deg;     /* 目标角度 */
} servo_unit_t;
```

几个设计点：

**`range_deg` 存在每颗身上**，不是全局常量。因为你的配置是 2 个单轴 + 2 个双轴，**双轴的虚轴可能装成 180° 模式**，行程不一样。

**`offset_deg`**：舵机装上去机械上总有几度偏差。机械调不准时，用这个字段在软件里补，不用改机构。

**`speed_dps` 存在每颗身上**：底座那颗 25kg 的大概能跑 300°/s，夹爪那颗要慢一点，各自独立。

**`cur_deg` 是软件推算的**，不是回读值。回读一次要 10ms，10ms 周期里做不了。

### 6.2 `deg_to_pwm()` —— 角度转脉宽

```c
int32_t d    = (int32_t)deg + (int32_t)u->offset_deg;
int32_t span = (int32_t)u->range_deg;
```
**为什么要 `(int32_t)` 强转**：`deg` 是 `int16_t`，`offset_deg` 也是。两个 `int16_t` 相加，结果还是 `int16_t`，**可能溢出**（32767 上限）。强转成 32 位再算就安全。

```c
if (d < 0)  { d = 0; }
if (d > span) { d = span; }
```
**双重保护**。即使上层传了 -50 或 300（已经越界），这里也夹住。**应用层不该相信任何输入**。

为什么要夹：舵机转到机械限位会**堵转**，25kg 的堵转电流能到 8A，几秒钟就烧。

```c
pwm = BUS_SERVO_PWM_MIN + (((d * 2000) + (span / 2)) / span);
```

**这是整个驱动里唯一需要想一下的公式**：

```
行程 0 ~ span  映射到  500 ~ 2500

pwm = 500 + (d / span) × 2000
```

举例（span = 270）：

| d（度） | 计算 | pwm |
|---|---|---|
| 0 | 500 + 0 | 500 |
| 135 | 500 + 135×2000/270 = 500+1000 | 1500 |
| 270 | 500 + 270×2000/270 = 500+2000 | 2500 |

**`+ (span / 2)` 是四舍五入**。不加的话，整数除法**永远向下取整**，比如 `134×2000/270 = 992.59 → 992`，每次都少一点，累积起来就是几度的误差。

**`2000` 不是 `1000`**：跨度是 `2500 - 500 = 2000`。我第一版写成 1000，舵机只能转到一半行程。

### 6.3 `step_per_tick()` —— 限速

```c
int16_t step = (int16_t)(((uint32_t)u->speed_dps + 50U) / 100U);
```

`speed_dps` 是"度/秒"，但函数是 **10ms 调一次**，所以：

```
每 10ms 走多少度 = speed_dps × 0.01 = speed_dps / 100
```

300°/s → 每 10ms 走 3°。

`+50U` 又是四舍五入（除以 100，加 50 相当于加 0.5）。

```c
if (step < 1) { step = 1; }
```
**防止除出 0**。如果 speed 设成 50°/s，`50/100 = 0`，舵机永远不动。设成最小 1°，慢但能动。

**为什么必须限速**（这不是可选项）：

四颗 25kg 舵机同时从 0° 冲到 270°：
```
瞬时电流：4 × 2A = 8A
8V 那路线径不够 → 电压瞬间掉到 5V
→ STM32 掉电复位
```
**这是真实会发生的**。限速后电流峰值降到 2~3A，就能稳住。

### 6.4 `ServoApp_Task()` —— 周期任务

```c
if (s_servo[i].cur_deg == s_servo[i].tgt_deg)
{
  continue;
}
```
**已经到位的舵机直接跳过**。省总线带宽，也省 CPU。

四个舵机都到位时，这个函数**什么都不做**，总线上一个字节都不发。

```c
if (s_servo[i].cur_deg < s_servo[i].tgt_deg)
{
  s_servo[i].cur_deg += step;
  if (s_servo[i].cur_deg > s_servo[i].tgt_deg)
  {
    s_servo[i].cur_deg = s_servo[i].tgt_deg;
  }
```
**"走一步，然后夹住"**。如果只加不减，`cur` 会冲过目标值，然后下一周期往回走，**来回抖动，永远停不下来**。

```c
ids[count]  = s_servo[i].id;
pwms[count] = deg_to_pwm(&s_servo[i], s_servo[i].cur_deg);
count++;
```
**只把"这一周期真的动了"的舵机放进帧里**。没动的不用发——发了也是重复指令，白占总线。

```c
s_last_status = BusServo_SetPwmSync(ids, pwms, count, SERVO_MOVE_TIME_MS);
```
`SERVO_MOVE_TIME_MS = 15`，比周期 10ms 略长。

**为什么不是 10ms**：如果给舵机 10ms 走完 3°，但 10ms 后新指令就到了，舵机会**刚好停一下就重启**，动作一顿一顿的。给 15ms，新指令在它走完之前到达，会**平滑接上**。

### 第 1 步：`USER CODE BEGIN Includes`

```c

```

### 第 2 步：`USER CODE BEGIN 2`

```c
/* USER CODE BEGIN 2 */
ServoApp_Init(&huart3);          /* 绑定串口，四颗摆到中点 */
printf("servo init: %d\r\n", ServoApp_LastStatus());

printf("present mask: 0x%02X\r\n", mask);   /* 0x0F = 四颗都在 */
/* USER CODE END 2 */
```

### 第 3 步：主循环里每 10ms 调一次

```c
/* USER CODE BEGIN WHILE */
uint32_t tick = HAL_GetTick();

while (1)
{
  if ((HAL_GetTick() - tick) >= SERVO_TASK_PERIOD_MS)
  {
    tick += SERVO_TASK_PERIOD_MS;
    ServoApp_Task();
  }

  /* 这里放你的测试动作，例如每 2 秒在 45° 和 225° 之间来回 */
  /* USER CODE END WHILE */
  /* USER CODE BEGIN 3 */
}
/* USER CODE END 3 */
```

**注意 `tick += 10` 而不是 `tick = HAL_GetTick()`**：
- `tick += 10`：周期严格 10ms，不累积误差
- `tick = now`：每次都有几微秒的漂移，一分钟后偏几十毫秒

### 想让舵机动一下（测试用）

```c
static uint32_t last = 0;
if ((HAL_GetTick() - last) > 2000U)
{
  last = HAL_GetTick();
  static int16_t a = 45;
  ServoApp_SetAll((int16_t[]){a, a, a, a});
  a = (a == 45) ? 225 : 45;
}
```

`(int16_t[]){...}` 是**复合字面量**（C99 起支持），临时造一个数组传给函数，不用先定义变量。

## 八、板子回来后的上板顺序

**不要一上来就接四颗。** 按这个顺序，每步都能独立判断对错：

| 步骤 | 做什么 | 怎么判断成功 |
|---|---|---|
| 1 | 不接舵机，只接 USB-TTL | 串口助手能看到 `servo init: 0` |
| 2 | 量 CN1 的 2 脚对 3 脚 | 万用表 8V 左右 |
| 3 | **只接 1 颗**，ID 还是 0 | `mask` 打印出 `0x00`（因为代码找的是 ID 1~4） |
| 4 | 把第 3 步那颗改成 ID=1 | 单独发 `#000PID001!`，收到 `#001P!` |
| 5 | 接 4 颗 | `mask` 打印 `0x0F` |
| 6 | 调 `ServoApp_SetAll` 让它动 | 四颗同时转向 |

**第 3 步的 `0x00` 是正常的**，不要以为代码坏了——代码里写死找 ID 1~4，而新舵机出厂是 ID 0。

### 改 ID 的小工具

在 `USER CODE BEGIN 2` 里临时加：

```c
printf("set id -> %d\r\n", BusServo_SetId(0, 1));   /* 把唯一的 0 号改成 1 号 */
```

**改 ID 必须一颗一颗来**：只接一颗，发指令，听到"咔"一声，断电，接下一颗。

## 九、故障对照表

| 现象 | 最可能的原因 | 查什么 |
|---|---|---|
| `mask = 0x00`，但舵机有电 | ID 不是 1~4 | 先 `Ping(0)` 试试 |
| 全部 `ERR_TIMEOUT` | 信号线没接 / 没上拉 | 量 PB10 对 3.3V 是不是 ≈5k |
| 全部 `ERR_FORMAT` | 波特率不对 | 确认 APB1=36MHz，HSE 起振 |
| 舵机抖动、来回摆 | 限速太高 / 电源不够 | 调小 `speed_dps`，量 8V |
| 一颗动，三颗不动 | ID 重复 | 一颗一颗单独接，`Ping` 确认 |
| 上电就复位 | 四颗同时启动拉塌电源 | 调小 `speed_dps`，加电容 |
| `printf` 没输出 | `__io_putchar` 没写 | 见上一轮对话 |

## 十、还没做的（板子回来后补）

1. **回读闭环**：现在 `cur_deg` 是软件推算的，堵转了也不知道。可以每 500ms `BusServo_ReadPwm()` 校准一次
2. **温度保护**：`BusServo_ReadTempVolt()` 已经写好了，但没接进 `Task`。超 60° 应该自动卸力
3. **超时保护**：现在 `Task` 里发失败只记录 `s_last_status`，没有重试。比赛时可以加"连续失败 5 次就报警"
4. **中断/DMA 收发**：现在全是阻塞式。10ms 周期里阻塞 5ms 发 67 字节，CPU 有 50% 在等串口。数据量再大就要换 DMA
